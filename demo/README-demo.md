# العرض التجريبي المحمول (ماك أو لينكس)

خادم ببيانات **وهمية** (نواب ولجان وأسئلة في كل الحالات)، بقاعدة SQLite ومفاتيح مؤقتة، لا علاقة له بالخادم الحقيقي.

## 1) تشغيل الخادم على الماك (مرة واحدة ثم متى شئت)
```
git clone https://github.com/mouhnadjib/apw-system
cd apw-system
./demo/run_demo.sh
```
- أول تشغيل يثبّت المكتبات (دقيقة أو دقيقتان، يلزم إنترنت لمرة واحدة)، ثم يعبّئ البيانات ويطبع **عنوان الخادم** (مثل `http://192.168.43.20:8000`) وبيانات الدخول والرموز (تُحفظ في `demo/DEMO-CODES.txt`).
- سيسأل macOS عن السماح بالاتصالات الواردة لـ Python: اختر **Allow**.
- لإعادة البيانات إلى حالتها الأولى: `./demo/run_demo.sh --reset`
- لإيقافه: `Ctrl+C`.

## 2) الشبكة
- وصّل الماك بنقطة اتصال الهاتف (أو راوتر)، وتأكد أن الهاتف على الشبكة نفسها.
- اختبار: من متصفح الهاتف افتح `http://عنوان-الماك:8000/health`، يجب أن يظهر `{"ok":true}`.
- إن لم يفتح وكان الهاتف هو صاحب نقطة الاتصال، فاستعمل هاتفاً ثانياً كنقطة اتصال.

## 3) بناء تطبيق العرض (مرة واحدة على أي جهاز فيه Flutter)
```
cd mobile
flutter build apk --debug --dart-define=DEMO_MODE=true
```
الناتج: `mobile/build/app/outputs/flutter-apk/app-debug.apk`. انقله إلى الهاتف وثبّته.
نسخة العرض تسمح باتصال http المحلي وتُظهر في شاشة التفعيل زر **الخادم**، فتكتب فيه عنوان الماك مرة واحدة ويُحفظ.
لا توزّع هذه النسخة على النواب، فهي للعرض فقط.

## 4) العرض
- **لوحة الديوان** على الماك: `http://localhost:8000/panel/` — `admin` أو `cabinet` وكلمتا المرور (عشوائيتان في كل تعبئة) في `demo/DEMO-CODES.txt`
- **التطبيق:** اضغط «الخادم» وأدخل العنوان، ثم فعّل نائباً برقمه ورمزه من `DEMO-CODES.txt` (مثلاً النائب الأول للأسئلة الجاهزة).
- مسار مقترح: أرسل إشعاراً من اللوحة ← يصل للهاتف ← أرسل سؤالاً من التطبيق ← أعده من اللوحة بملاحظة ← عدّله من التطبيق ← أكّده وأحِله وارفع رداً ← افتحه في التطبيق.

## تنبيه أمني
الخادم التجريبي يستمع على الشبكة المحلية ببيانات وهمية. لا تعرضه على الإنترنت عبر نفق إلا لعرض قصير ثم أطفئه، وبياناته لا تمثل شيئاً حقيقياً.
